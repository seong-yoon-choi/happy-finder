Happy Finder New Plan
작성 기준일: 2026-05-14
최근 업데이트: 2026-05-19

1. 현재 제품 방향

Happy Finder는 "다른 사람들은 언제 행복했는지 보고, 나도 따라 해보고, 내 일상의 행복을 기록하고 공유하는 앱"으로 간다.

중요한 방향:
- AI는 바로 출시 기능으로 넣지 않는다.
- 3단계 태그 시스템까지 포함해 AI 없이도 충분히 쓸 수 있는 앱을 먼저 완성한다.
- AI는 비용이 드는 기능이므로, 비AI 버전의 사용자 반응을 본 뒤 붙인다.
- 앱의 핵심은 기능 수가 아니라 "행복을 쉽게 발견하고 부담 없이 기록하는 흐름"이다.

현재 원칙:
- 리스트 카드는 탐색과 확인 중심으로 단순하게 둔다.
- 수정, 삭제, 공유, 사진 저장 같은 액션은 상세 모달 안에 둔다.
- 카메라, 앨범, 저장 기능은 기록 모달과 행복 리스트 메모 모달 모두에 있어야 한다.
- 태그는 행복 리스트에만 적용한다.
- 자유 기록과 행복 메모에는 태그를 붙이지 않는다.
- 태그는 홈 검색/필터와 행복 리스트 탐색을 강화하는 용도로 먼저 완성한다.
- 분석 화면과 태그 연결은 출시 전 마감 단계에서 별도 정리한다.
- 좋아요처럼 보이는 평가/랭킹 기능은 현재 MVP에서 제외한다.
- 대신 공감 기능은 상세 모달 안에 작은 흔적으로만 남긴다.
- 공감은 보관함이나 정렬 기준으로 쓰지 않는다.
- 공감은 "나도 이 마음을 알아요"에 가까운 따뜻한 반응으로 둔다.
- 리스트 정렬 옵션은 현재 MVP에서 제외하고, 기본 탐색 흐름을 먼저 단순하게 유지한다.
- 즐겨찾기와 공유는 기존 구조를 유지한다.
- 분석 기능으로 넘어가기 전, 공유 경로 선택 모달과 알림 시간 선택 방식 같은 세부 UX를 먼저 정리한다.
- 알림 시간은 오전/오후 없이 00시부터 23시까지 24시간제로 선택한다.

제품 정체성:
- Happy Finder는 행복을 정답처럼 알려주는 앱이 아니다.
- 누군가가 언제 행복했는지 보여주고, 사용자가 그 행복을 자기 일상에 가져와 볼 수 있게 돕는다.
- "이렇게 하면 행복합니다"보다 "나는 이렇게 해보니 행복했어요"에 가까운 문장 톤을 사용한다.
- 기본 행복 리스트 문구는 명령형보다 경험 공유형 문장으로 정리한다.
- 사용자는 다른 사람의 행복 경험을 보고 따라 해볼 수 있고, 자신의 행복도 사진과 글로 남길 수 있다.

협업 / 말하기 규칙:
- 사용자의 말을 100% 이해했고 실행 방향이 명확하면 바로 실행한다.
- 이해가 애매하거나 구현 방식이 여러 갈래라면, 먼저 "내가 이해한 게 이게 맞는지" 확인한다.
- 기능 수정이나 추가 요청을 받으면, 바로 코딩만 하지 않고 더 나은 아이디어, 보완점, UI/UX 관점의 추천을 먼저 말한다.
- 단순 코딩 도구처럼 행동하지 않고, 사업 파트너처럼 제품 방향, UI/UX, 마케팅, 운영 관점까지 함께 고민한다.
- 최초 아이디어는 사용자가 내고, 그 아이디어를 제품적으로 발전시키는 과정은 함께 만든다.
- 코드 수정 뒤에는 항상 AAB 최신화와 커밋/푸시 진행 여부를 사용자에게 확인한다.
- 확신 없이 임의로 진행하면 안 되는 작업은 먼저 짧게 확인하고 진행한다.


2. 이미 구현된 주요 내용

1단계: 홈 / 리스트 MVP 정리
- 기존 카테고리 중심 구조 제거.
- 길게 눌러 행복을 찾는 흐름 제거.
- 스탬프와 찾은 횟수 중심 구조 제거.
- 홈에 검색창 형태의 영역, 태그 아이콘 버튼, 플러스 버튼 추가.
- 플러스 버튼으로 내 행복 만들기 진입 가능.
- 홈 색감을 초록/노랑 계열로 변경.
- 하트 저장 기능은 기존 즐겨찾기 구조를 유지하되 내 행복 개념으로 사용.
- 행복 리스트 카드에는 액션 버튼을 과하게 노출하지 않는 방향으로 정리.
- 메모가 있는 행복 카드에는 노트 아이콘과 메모 개수를 상태 정보로 표시.
- 공유 버튼은 리스트 카드에서 제거하고, 행복 상세 모달 안에만 둠.

2단계: 기록 기능
- 하단 네비게이션에 기록 탭 추가.
- 기록 화면 추가.
- 자유 기록 작성 기능 추가.
- 기록 제목 입력 추가.
- 기록 내용 입력 추가.
- 카메라/앨범 사진 첨부 기능 추가.
- 사진을 앱 안에서만 볼 수 있게 저장하는 구조 구현.
- 사진을 휴대폰 갤러리에 저장하는 버튼 추가.
- 기록 리스트는 제목과 내용 한 줄 중심으로 축소.
- 기록을 누르면 상세 모달에서 전체 내용 확인 가능.
- 기록 상세 모달 안에 수정, 삭제, 공유 아이콘 배치.
- 수정/삭제는 텍스트 버튼이 아니라 아이콘 버튼으로 변경.
- 삭제 아이콘은 가로로 넓고 선은 얇은 형태로 조정.
- 공유 아이콘은 종이비행기 형태로 통일.
- 공유 기능은 공유 경로 선택 모달을 통해 실제 동작하도록 정리.

2단계: 기록 보기 방식
- 기록 화면은 기록 / 행복 메모 탭으로 나눈다.
- 두 탭 모두 일 / 달 / 모두 보기 방식을 사용한다.
- 일 보기에서는 주간 날짜 스트립을 표시한다.
- 좌우 화살표로 일주일 단위 이동.
- 주가 바뀌며 월이 넘어가면 중앙 년월도 변경.
- 날짜를 누르면 해당 날짜 기록 또는 행복 메모로 아래 리스트가 변경.
- 오늘 날짜는 초록 단일 테두리로 표시한다.
- 기록이 있는 날짜는 노란 점으로 표시.
- 달 보기에서는 주간 날짜 스트립과 달력 모달 없이 년월만 표시하고, 해당 월의 모든 기록 또는 행복 메모를 보여준다.
- 모두 보기에서는 년월일 선택 UI 없이 전체 기록 또는 전체 행복 메모를 보여준다.
- 기록 남기기는 기록 탭 우측 하단 플로팅 버튼으로 진입한다.
- 행복 메모 탭에는 기록 남기기 버튼을 표시하지 않는다.
- 일요일은 빨간색, 토요일은 파란색으로 표시.
- 공휴일도 빨간색 계열로 표시하는 방향 적용.

2.5단계: 분석 화면 뼈대
- 하단 네비게이션을 홈 / 기록 / 분석 / 프로필 구조로 확장.
- 분석 화면 뼈대 추가.
- 원형 그래프 영역을 분석 화면 상단에 배치.
- 최근 기록, 이번 달, 최근 7일, 전체 기록 같은 중복 통계는 제거.
- AI 분석은 아직 붙이지 않고, 나중에 들어갈 자리만 준비.
- 태그 분석은 아직 행복 리스트 태그와 제대로 연결되지 않은 상태로 본다.

프로필 정리
- 프로필 상단의 중복 숫자 컨테이너 제거.
- 즐겨찾기와 만든 행복 수량은 중앙 선택 탭에서만 표시.
- 추후 분석 기능이 고도화되면 프로필 상단 빈 공간에는 "나의 행복 스타일" 요약을 넣을 예정.
- Q 버튼과 설정 버튼은 홈/기록/프로필 흐름에서 사용할 수 있도록 유지.


3. 현재 막 정리한 기록 탭 구조

기록 화면 상단의 "기록" 문구 옆에 "행복 메모" 탭을 추가했다.

현재 구조:
- 기록
- 행복 메모

UI 원칙:
- 활성화된 탭은 진하게 표시.
- 비활성화된 탭은 연하게 표시.
- 별도 박스형 탭 바를 만들지 않고, 기존 제목 위치에서 자연스럽게 전환.
- 기록 탭은 사용자가 직접 남긴 자유 기록만 보여준다.
- 행복 메모 탭은 행복 리스트 상세 모달에서 남긴 메모만 모아서 보여준다.
- 행복 메모를 누르면 연결된 행복 상세 모달이 열리고, 선택한 메모 위치로 바로 포커스된다.

추천 방향:
- 기록 탭은 사용자가 직접 남긴 자유 기록을 보여준다.
- 행복 메모 탭은 행복 리스트 상세 모달에서 남긴 메모만 모아서 보여준다.
- 두 데이터는 내부적으로 분리하되, 같은 기록 화면 안에서 볼 수 있게 한다.
- 기록과 행복 메모를 "전체 / 기록 / 행복 메모"로 섞는 방식은 쓰지 않는다.
- 사용자가 보기에는 기록 화면 안에 두 개의 하위 탭이 있는 구조가 더 명확하다.


4. 2.7단계 MVP 목표

3단계 태그 시스템에 들어가기 전, 기록과 행복 리스트 메모 경험을 더 완성한다.

2.7단계 핵심 목표:
1. 기록 리스트 보기 방식 정리
2. 행복 메모 탭 실제 구현
3. 이미지가 있는 기록과 행복 메모의 리스트 UI 정리
4. 기록 모달과 행복 리스트 메모 모달의 사진 UX 통일
5. 리스트 카드 액션 최소화 원칙 확정
6. 태그 시스템이 들어갈 자리 확보

2.7단계 현재 완료:
- 행복 메모 탭을 실제 행복 리스트 메모 데이터와 연결.
- 행복 메모를 누르면 해당 행복 상세 모달에서 선택한 메모로 바로 포커스.
- 기본 행복 리스트 중 "일기 쓰기"에 샘플 이미지 썸네일 1개 적용.
- 기록과 행복 메모 리스트에 우측 1/3 이미지 썸네일 적용.
- 기록과 행복 메모 모두 일 / 달 / 모두 보기 방식 적용.
- 기록 남기기는 우측 하단 플로팅 버튼으로 이동.
- 기록 모달과 행복 리스트 메모 모달의 사진 UX를 최대한 통일.
- 카메라로 찍은 사진만 앨범 저장 버튼을 표시.
- 앨범에서 가져온 사진은 저장 버튼을 숨김.
- 리스트 카드 액션 최소화 원칙 유지.

2.7단계에서 남긴 것:
- 기록 / 행복 메모는 기능 추가보다 실제 기기 QA와 빈 상태 문구 마감이 우선이다.
- 사진형/피드형 보기 방식은 지금 바로 구현하지 않고, 실제 사용 필요성이 확인되면 추가한다.
- 공유 기능은 분석 전 세부 기능 마감 항목으로 먼저 실제 동작을 붙인다.


5. 기록 / 행복 메모 보기 방식

현재 보기 방식은 시간 범위 기준 3가지로 나눈다.

1. 일
- 기본 보기 방식.
- 주간 날짜 스트립을 보여준다.
- 선택한 날짜의 기록 또는 행복 메모만 보여준다.
- 오늘 날짜는 초록 단일 테두리로 표시한다.
- 기록이 있는 날짜는 노란 점으로 표시한다.

2. 달
- 주간 날짜 스트립과 달력 모달은 보여주지 않는다.
- 년월만 표시한다.
- 선택한 월에 남긴 모든 기록 또는 행복 메모를 보여준다.
- 월 이동은 좌우 화살표로 처리한다.

3. 모두
- 년월일 선택 UI를 보여주지 않는다.
- 사용자가 남긴 모든 기록 또는 행복 메모를 최신순으로 보여준다.

리스트 카드 표시:
- 제목, 내용 한 줄, 작성 시간, 우측 이미지 썸네일을 표시한다.
- 이미지가 있으면 카드 오른쪽에 정사각형 썸네일을 둔다.
- 썸네일은 카드 가로 폭의 약 1/3 정도를 차지한다.
- 이미지가 없으면 기존 텍스트 카드처럼 보이게 한다.

추가로 검토할 보기 방식:
- 사진형/피드형은 현재 MVP 범위에서는 보류한다.
- 실제 사용자 기록에 사진이 충분히 쌓인 뒤 필요성이 확인되면 추가한다.


6. 행복 메모 탭 UI/UX 방향

행복 메모는 기록과 같은 화면 안에 있지만 성격은 다르다.

기록:
- 리스트와 연결되지 않은 자유 기록.
- 하루의 생각, 감정, 일기, 사진 기록.

행복 메모:
- 특정 행복 리스트 항목에 붙인 메모.
- 예: "맛있는 점심 먹기" 항목에 남긴 오늘의 메모.

행복 메모 탭에서 보여줄 정보:
- 연결된 행복 제목
- 메모 내용 한 줄
- 작성 시간
- 이미지가 있으면 썸네일
- 행복 메모 자체 태그는 표시하지 않는다.
- 연결된 행복 리스트의 태그를 행복 메모 카드에 직접 노출할지는 보류한다.

행복 메모 탭 카드 예시:

[행복 제목]
[메모 내용 한 줄]
[시간]
[우측 이미지 썸네일]

행복 메모를 누르면:
- 행복 리스트 상세 모달 또는 행복 메모 상세 모달로 이동.
- 그 안에서 수정, 삭제, 공유, 사진 저장 가능.

주의:
- 행복 메모 탭에서 바로 수정/삭제 버튼을 노출하지 않는다.
- 리스트는 탐색 중심, 액션은 모달 중심 원칙을 유지한다.


7. 모달 액션 정책

리스트 카드에 직접 액션 버튼을 늘리지 않는다.

리스트 카드에 보여도 되는 것:
- 제목
- 설명 또는 내용 한 줄
- 이미지 썸네일
- 노트/메모 개수
- 행복 리스트 카드의 태그 일부
- MY 배지

리스트 카드에 숨기는 것:
- 수정
- 삭제
- 공유
- 카메라
- 앨범
- 저장

모달 안에 배치할 것:
- 수정
- 삭제
- 공유
- 카메라
- 앨범
- 사진 저장
- 기록 저장

현재 결정:
- 공유 버튼은 행복 리스트 카드와 기록 리스트 카드에서는 보이지 않게 한다.
- 공유 버튼은 행복 상세 모달과 기록 상세 모달 안에만 둔다.
- 공유 기능은 행복 상세 모달과 기록 상세 모달에서 공유 경로 선택 모달로 동작한다.


8. 3단계 태그 시스템

3단계는 AI 없이 구현한다.
태그 시스템은 출시 전 핵심 기능 중 하나로 본다.

태그 시스템 목표:
- 홈 검색과 필터를 강화한다.
- 행복 리스트를 나중에 쉽게 분류한다.
- AI가 없어도 사용자가 원하는 행복 리스트를 찾기 쉽게 만든다.

2층 태그:
- 사용자에게 보이는 태그.
- 검색, 필터, 기록 정리에 사용.

최종 2층 태그:

상황
- 혼자
- 함께
- 실내
- 실외

조건
- 짧게
- 길게
- 무료
- 유료

상태
- 활동적
- 휴식

감정
- 즐거움
- 편안함
- 설렘
- 뿌듯함
- 위로
- 감동
- 새로움

1층 행복 유형:
- 사용자 화면에는 직접 노출하지 않는다.
- 분석용 내부 데이터로 둔다.
- AI를 붙이기 전에는 수동 데이터 또는 기본 매핑으로 준비할 수 있다.

1층 유형:
- 감각적 행복
- 성취적 행복
- 관계적 행복
- 몰입적 행복
- 의미적 행복

원칙:
- 하나의 행복 리스트는 1~3개의 태그를 가질 수 있다.
- 자유 기록과 행복 메모에는 태그를 붙이지 않는다.
- 1층 행복 유형은 분석용으로만 검토하고, AI 도입 전까지 저장/노출하지 않는다.
- 1층 행복 유형을 도입할 때는 각 유형이 가중치를 가질 수 있다.
- 유형 가중치 합계는 10점 기준으로 관리하는 방향을 검토한다.


9. AI 도입 전략

AI는 5단계 이후로 미룬다.

이유:
- AI API 비용이 든다.
- 먼저 AI 없이도 사람들이 쓰는지 확인해야 한다.
- 기록, 태그, 검색, 이미지 보기, 행복 메모 구조가 안정된 뒤 AI를 붙여야 한다.

AI 없이 먼저 출시할 기능:
- 행복 리스트
- 내 행복 만들기
- 즐겨찾기/내 행복
- 자유 기록
- 행복 메모
- 사진 첨부
- 캘린더
- 분석 화면 뼈대
- 태그 검색/필터
- 이미지 보기 모드

AI 도입 후 기능:
- 기록 한 줄 요약
- 태그 자동 추천
- 행복 유형 가중치 추천
- 최근 행복 패턴 분석
- 추천 행복 제안
- 프로필의 나의 행복 스타일 요약

AI 구조 원칙:
- 모바일 앱에 API 키를 넣지 않는다.
- Supabase Edge Function 또는 별도 서버에서 AI API를 호출한다.
- 분석 데이터 사용은 약관과 개인정보 동의에 포함한다.


10. 다음 구현 순서 제안

현재 판단:
- 기록과 행복 메모는 큰 기능 추가보다 QA 마감 단계로 본다.
- 행복 리스트 태그 시스템은 분석 영역 연결을 제외하면 대부분 구현된 상태로 본다.
- 다음 작업은 태그를 더 크게 확장하기보다, 태그 기반 분석과 출시 전 안정성 점검으로 넘어간다.

2.7-1. 행복 메모 탭 실제 연결
- 완료.
- 행복 리스트 상세 모달에서 작성한 메모를 기록 화면의 행복 메모 탭에 모아 보여준다.
- 자유 기록과 행복 메모는 내부적으로 분리 유지.
- 행복 메모를 누르면 해당 행복 상세 모달에서 선택한 메모 위치로 포커스된다.

2.7-2. 기본 리스트형 이미지 썸네일
- 완료.
- 기본 행복 리스트 중 한 항목에 샘플 이미지 썸네일 적용.
- 기록 카드와 행복 메모 카드의 우측 1/3 이미지 썸네일 적용.
- 이미지가 없는 경우 기존 텍스트형 유지.

2.7-3. 보기 방식 전환 UI
- 완료.
- 기록 탭과 행복 메모 탭 모두 일 / 달 / 모두 보기 방식을 공유한다.
- 사진형 / 피드형은 MVP 범위에서 보류한다.

2.7-4. 모달 사진 UX 통일
- 완료에 가깝다.
- 기록 모달과 행복 리스트 메모 모달 모두 카메라/앨범/저장 기능을 갖도록 정리.
- 카메라 촬영 사진만 앨범 저장 버튼을 표시한다.
- 앨범에서 가져온 사진은 저장 버튼을 숨긴다.
- 남은 작업은 실제 기기에서 권한 거부, 앨범 선택, 사진 저장 실패 흐름 QA.

2.7-5. 공유 버튼 정책 정리
- 모달 안에만 노출.
- 행복 상세 모달과 기록 상세 모달에서 공유 경로 선택 모달을 띄운다.
- 공유 경로는 카카오톡, 인스타그램, X/트위터, 링크 복사를 기본 선택지로 둔다.

3-1. 태그 데이터 구조 추가
- 완료에 가깝다.
- 행복 리스트 항목에 tags 추가.
- 자유 기록에는 tags를 추가하지 않는다.
- 행복 메모에는 tags를 추가하지 않는다.
- 사용자가 직접 만드는 행복 리스트에도 태그를 최대 3개까지 선택하게 한다.
- Supabase tags 컬럼과 마이그레이션 SQL 준비.
- 1층 행복 유형과 가중치는 AI 도입 전까지 보류한다.
- 우리가 만든 기본 행복 리스트에는 2층 태그를 미리 부여한다.

3-2. 홈 검색/태그 필터 구현
- 완료에 가깝다.
- 검색 대상: 제목, 설명, 태그.
- 태그 선택 모달 구현.
- 선택한 태그 중 하나라도 포함된 행복을 보여주는 OR 방식으로 시작한다.

3-3. 행복 리스트 태그 표시
- 완료에 가깝다.
- 행복 리스트 카드에는 태그 일부만 표시.
- 행복 상세 모달에서 전체 태그를 표시한다.
- 기록과 행복 메모 화면에는 태그를 표시하지 않는다.

3-4. 태그와 분석 연결
- 남은 핵심 작업.
- 분석 화면에서 행복 리스트 태그를 어떤 지표로 보여줄지 결정한다.
- 예: 자주 선택한 행복 태그, 내가 만든 행복의 태그 분포, 즐겨찾기 태그 분포.
- 자유 기록과 행복 메모에는 태그가 없으므로 분석 계산 대상에서 제외하거나 텍스트 키워드 분석으로만 다룬다.
- 1층 행복 유형 분석은 AI 도입 전까지 보류한다.

3-5. 공유 기능 구현
- 행복 상세 모달과 기록 상세 모달에 있는 공유 버튼에 실제 동작을 붙인다.
- 리스트 카드에는 공유 버튼을 노출하지 않는다.
- 공유 내용은 제목, 설명 또는 기록 내용 일부, Happy Finder 출처를 포함하는 방향으로 검토한다.
- 카카오톡/인스타그램은 별도 SDK를 붙이기 전까지 기기 기본 공유창을 통해 선택하게 한다.
- X/트위터는 작성창을 열고, 링크 복사는 공유 내용을 클립보드에 저장한다.

3단계 현재 결정:
- 기록 작성/수정 모달에는 태그 기능을 넣지 않는다.
- 내 행복 만들기 모달에는 태그 선택 기능을 넣고, 사용자가 만든 행복도 검색/필터 대상이 되게 한다.
- 행복 메모는 특정 행복 항목에 붙은 개인 메모이므로 별도 태그를 달지 않는다.
- 기본 행복 리스트에는 우리가 정한 2층 태그를 임의 부여한다.
- Supabase happiness_items에는 tags text[] 컬럼을 추가해 공개 행복도 태그를 저장할 수 있게 한다.
- 1층 행복 유형은 분석용 내부 데이터지만, AI를 붙이기 전까지는 저장/노출하지 않는다.
- 태그와 분석 화면 연결은 아직 남은 작업이다.
- 공유 기능은 분석 전 세부 UX 정리 항목으로 먼저 구현한다.

3단계 구현 반영:
- 홈 검색은 제목, 설명, 태그를 대상으로 한다.
- 홈 태그 필터는 선택한 태그 중 하나라도 포함된 행복을 보여주는 OR 방식으로 시작한다.
- 내 행복 만들기에서는 최소 1개, 최대 3개 태그를 선택하게 한다.
- 행복 리스트 카드와 행복 상세 모달에 태그 표시를 적용한다.
- 기록과 행복 메모에는 태그 UI를 넣지 않는다.
- 공유 기능은 행복 리스트 카드가 아니라 행복 상세 모달과 기록 상세 모달 안에서만 동작한다.
- Supabase 태그 컬럼은 root SQL과 migrations SQL 둘 다 준비한다.


11. 제품 판단 원칙

앞으로 기능을 추가할 때 항상 이 기준으로 판단한다.

1. 사용자가 기록하기 쉬워지는가?
2. 화면이 복잡해지지 않는가?
3. 나중에 태그와 AI가 붙어도 구조가 버틸 수 있는가?
4. 리스트 카드는 탐색 중심인가?
5. 중요한 액션은 모달 안에 모여 있는가?
6. AI 없이도 앱을 계속 쓸 이유가 있는가?

정리 문장:

Happy Finder는 행복을 정답처럼 알려주는 앱이 아니다.
사람들이 언제 행복했는지 보여주고, 사용자가 그 행복을 자기 일상에 가져와 보고,
사진과 글로 남긴 기록을 통해 나중에 자신의 행복 패턴을 이해하도록 돕는 앱이다.


12. MVP 단계별 요약

MVP 1단계: 홈 / 행복 리스트 정리
- 홈을 행복 리스트 중심으로 단순화.
- 카테고리 중심 구조와 길게 누르는 흐름 제거.
- 검색창 자리, 태그 버튼 자리, 행복 추가 버튼 자리 확보.
- 즐겨찾기 구조를 유지해 마음에 드는 행복을 저장하는 흐름으로 사용.
- 홈 색감을 초록/노랑 계열로 정리.

MVP 2단계: 기록 기능
- 기록 탭 추가.
- 자유 기록 작성, 제목, 내용, 사진 첨부, 사진 저장 기능 구현.
- 기록은 리스트에서 한 줄로 보고, 상세 모달에서 전체 내용을 확인.
- 수정, 삭제, 공유 아이콘은 상세 모달 안에 배치.

MVP 2.5단계: 분석 화면 뼈대
- 하단 네비게이션을 홈 / 기록 / 분석 / 프로필로 확장.
- 분석 화면에 원형 그래프와 행복 스타일, 키워드, 추천 영역의 자리 마련.
- AI 분석은 붙이지 않고, 나중에 데이터가 들어올 구조만 준비.

MVP 2.7단계: 기록 / 행복 메모 마무리
- 기록 안에 기록 / 행복 메모 탭 구조 적용.
- 행복 메모 탭은 행복 리스트에 남긴 메모만 모아 보여준다.
- 행복 메모 클릭 시 연결된 행복 상세 모달에서 해당 메모로 포커스.
- 기본 행복 리스트에 샘플 이미지 썸네일 1개 적용.
- 기록과 행복 메모는 일 / 달 / 모두 보기 방식으로 정리.
- 기록 남기기는 우측 하단 플로팅 버튼으로 진입.
- 기본 카드는 리스트형 유지.
- 사진형/피드형 보기 방식은 이후 필요할 때 추가.

MVP 3단계: 태그 / 검색 / 공유
- 사용자에게 보이는 2층 태그를 행복 리스트에 적용.
- 홈 검색과 태그 필터 구현.
- 행복 리스트 카드에 태그 일부 표시.
- 행복 리스트 상세 모달에서는 태그를 표시하고, 기본 행복 태그는 앱에서 미리 부여.
- 내 행복 만들기에서도 사용자가 태그를 직접 선택.
- 태그와 분석 화면 연결은 아직 남은 작업.
- 공유 기능을 실제 동작하도록 구현.

MVP 3단계 수정:
- 태그는 행복 리스트에만 적용한다.
- 자유 기록에는 태그를 적용하지 않는다.
- 행복 메모에는 태그를 적용하지 않는다.
- 기본 행복 리스트 태그는 우리가 미리 부여한다.
- 사용자가 만든 행복 리스트 태그는 만들기 단계에서 직접 선택한다.
- 1층 행복 유형과 가중치 분석은 AI 도입 시점까지 보류한다.

MVP 4단계: 출시 전 완성도 점검
- 빈 상태, 권한 거부, 이미지 실패, 로그인/게스트 전환 같은 예외 흐름 정리.
- 모바일 실제 기기에서 홈, 기록, 행복 메모, 분석, 프로필 UX 점검.
- AAB, 앱 아이콘, 스토어 이미지, 약관/개인정보 문구 점검.

MVP 5단계 이후: AI 도입 검토
- AI는 초기 출시 반응을 본 뒤 붙인다.
- 태그 자동 추천, 행복 유형 가중치 추천, 기록 요약, 행복 패턴 분석, 추천 행복 제안을 검토한다.
- AI API 키는 앱에 직접 넣지 않고 Supabase Edge Function 또는 별도 서버에서 호출한다.
