Happy Finder 앱 설명 및 AI 인수인계 문서
최신 정리일: 2026-06-14


1. 문서 목적

이 문서는 Happy Finder를 처음 보는 AI가 앱의 정체성, 현재 출시 상태, 핵심 기능, 앞으로의 방향성을 빠르게 이해하도록 만든 설명서다.
이 파일은 단순 작업 로그가 아니라, 앞으로 개발/운영/마케팅/AI 기능 기획을 이어갈 때 기준점으로 사용한다.

중요:
- 사용자의 최신 요청이 항상 우선이다.
- 이 문서는 방향을 이해하기 위한 기준이지, 사용자의 최신 판단을 고정하는 틀이 아니다.
- 비밀키, 토큰, 환경변수 값은 절대 출력하지 않는다.
- OneDrive 경로가 보이더라도 실제 작업은 로컬 Desktop repo 기준으로 한다.


2. 앱 한 줄 설명

Happy Finder는 일상 속 작은 행복을 발견하고, 기록하고, 다른 사람의 행복에 공감하며, 내 행복 패턴을 분석해 볼 수 있는 앱이다.


3. 앱 정체성

초기 방향은 "행복 리스트를 보고 따라 해보는 앱"에 가까웠지만, 현재 방향은 더 넓어졌다.

현재 Happy Finder가 지향하는 경험:
- 나는 언제 행복했는지 짧게 기록한다.
- 다른 사람들은 어떤 순간에 행복했는지 둘러본다.
- 마음이 닿는 행복에는 공감한다.
- 마음에 드는 행복은 즐겨찾기하거나 메모를 남긴다.
- 쌓인 기록, 메모, 공감, 즐겨찾기, 태그를 바탕으로 내 행복 성향을 확인한다.

핵심 감성:
- 거창한 목표 달성이 아니라 작은 행복의 발견
- 부담스러운 일기보다 가볍고 짧은 기록
- 좋아요 경쟁보다 따뜻한 공감
- 분석은 차갑게 점수화하기보다 나를 이해하는 리포트처럼 제공


4. 현재 출시 상태

현재 앱은 출시 완료 상태다.

배포 버전 기준:
- Android: versionName 1.0.27, versionCode 28
- iOS: MARKETING_VERSION 1.0.27, CURRENT_PROJECT_VERSION 28

배포 관련 상태:
- Android AAB 최신화 완료
- iOS GitHub Actions 빌드 및 App Store Connect 업로드 완료
- Google Play / App Store 출시가 끝난 상태로 보고 있다.

이제 중심은 기능 추가가 아니라 운영, 마케팅, 사용자 반응 수집, 데이터 확인이다.


5. 현재 핵심 기능 요약

홈 / 행복 리스트:
- 기본 행복 리스트와 사용자가 만든 행복을 카드로 보여준다.
- 카드에는 이미지, 제목, 짧은 설명, 태그, 메모 여부, 공감 여부가 표시된다.
- 검색과 태그 필터를 제공한다.
- 검색 결과 없음, 태그 결과 없음, 즐겨찾기 없음, 내가 만든 행복 없음 같은 빈 상태 문구를 제공한다.
- 오늘의 행복 영역을 통해 사용자가 하루의 행복을 기록하도록 유도한다.

오늘의 행복:
- 홈 상단에서 오늘의 행복 기록을 유도한다.
- 아직 작성하지 않았으면 기록을 유도하는 빈 상태 카드가 보인다.
- 누르면 기록 작성 모달과 같은 흐름으로 기록을 남긴다.
- 저장된 오늘의 행복은 기록 데이터에 포함된다.

행복 만들기:
- 사용자가 직접 행복 항목을 만들 수 있다.
- 제목, 내용, 이미지, 태그를 입력한다.
- 이미지는 사용자가 추가하지 않으면 기본 세잎 클로버 이미지로 대체된다.
- 태그는 관계, 장소, 시간, 행동 4개 축에서 각각 1개씩 선택한다.
- 사용자가 만든 공개 행복에 다른 사용자가 공감하면 만든 사용자에게 알림이 가는 흐름이 있다.

기록:
- 사용자가 자유롭게 하루의 순간과 감정을 기록한다.
- 제목, 내용, 사진을 남길 수 있다.
- 일 / 월 / 모두 보기 구조로 기록을 확인한다.
- 일 보기에서는 날짜와 달력 기능을 사용한다.
- 월 보기에서도 날짜 선택이 가능하도록 달력 접근성을 보완했다.
- 기록 삭제처럼 실제 데이터가 사라지는 동작에는 확인 모달을 붙인다.

행복 메모:
- 행복 리스트 상세에서 메모를 남길 수 있다.
- 메모가 있는 항목은 카드 밖에서도 노트 아이콘으로 표시된다.
- 기록 탭 안에서 행복 메모를 별도 흐름으로 확인할 수 있다.
- 메모 삭제에도 확인 모달을 사용한다.

공감:
- 공감은 좋아요 경쟁이 아니라 "나도 이 마음을 알 것 같다"는 따뜻한 흔적이다.
- 공감 버튼은 얼굴 아이콘 기반이다.
- 누르기 전에는 무표정, 누른 후에는 웃는 얼굴 느낌으로 보여준다.
- 리스트 밖에서는 작은 공감 아이콘으로만 상태를 보여준다.
- 프로필에서 내가 공감한 행복을 확인할 수 있다.

즐겨찾기:
- 마음에 드는 행복을 저장하는 기능이다.
- 프로필에서 즐겨찾기 목록을 확인할 수 있다.
- 공감과 역할이 겹치지 않도록 즐겨찾기는 "다시 보고 싶은 항목", 공감은 "마음이 닿은 흔적"으로 본다.

공유:
- 행복 상세에서 공유할 수 있다.
- 공유 모달에는 카카오톡, 인스타그램, X, 링크 복사 같은 경로를 앱 아이콘 중심으로 보여준다.
- 실제 SDK 연동은 제한적일 수 있고, 현재는 네이티브 공유 / 링크 복사 중심의 흐름이다.

사진:
- 카메라 촬영과 앨범 선택을 지원한다.
- Google Play 정책 문제로 지속 미디어 권한은 제거했고, 필요한 순간에만 사진 선택 흐름을 사용한다.
- 사진은 리스트 이미지 비율에 맞도록 편집하는 흐름이 있다.
- 저장 전 사진 순서를 바꿀 수 있도록 터치 기반 정렬 기능을 구현했다.
- 리스트 카드에서는 첫 번째 이미지를 대표 이미지로 사용한다.

분석:
- AI 없이도 태그와 사용자 활동 데이터를 바탕으로 분석을 제공한다.
- 기록, 메모, 공감, 즐겨찾기, 태그 데이터가 분석에 반영된다.
- 관계 / 장소 / 시간 / 행동 4개 축의 비율을 막대 그래프로 보여준다.
- 4개 축 조합으로 행복 성향 유형을 보여준다.
- 이번주 행복 분석에서는 요일별 활동량을 꺾은선 그래프로 보여준다.
- 포인트를 누르면 해당 날짜의 활동 요약을 말풍선 형태로 보여준다.
- 추천 행복은 사용자의 태그 흐름과 가까운 항목을 제안하는 방식이다.

프로필:
- 로그인 계정 기반 사용을 중심으로 한다.
- 게스트 사용 흐름은 제거하는 방향으로 정리했다.
- 즐겨찾기, 내가 만든 행복, 내가 공감한 행복을 확인할 수 있다.
- 내가 만든 행복 상세에서는 삭제 버튼을 아이콘 중심으로 제공한다.

웹:
- 앱 소개, 로그인, 문의/피드백, 법적 정보 페이지를 제공한다.
- 앱의 현재 기능과 감성에 맞게 문구를 정리했다.
- Google 로그인 위치, 로그아웃 버튼, 개인정보/약관 동의 문구를 수정했다.
- 웹은 앱을 보조하는 소개/문의/법적 정보 채널로 본다.


6. 태그와 분석 기준

현재 사용자에게 보이는 태그 축은 4가지다.

관계:
- 혼자
- 함께

장소:
- 실내
- 실외

시간:
- 짧게
- 길게

행동:
- 활동
- 휴식

중요한 결정:
- 무료 / 유료 태그는 제거했다.
- 이유는 같은 행동도 사람마다 무료인지 유료인지 다르게 느낄 수 있기 때문이다.
- 감정 태그도 현재는 제거했다.
- 감정은 사람마다 주관적이므로 AI 도입 후 기록 문장과 맥락을 기반으로 분석하는 편이 더 적합하다.

분석 방식:
- 행복 항목에는 4개 축에서 각각 1개씩 총 4개의 태그가 붙는다.
- 4개 축 조합으로 16가지 성향 유형을 만들 수 있다.
- 분석은 단순히 "혼자 태그가 많다"라고 말하는 방식이 아니라, 혼자 중심 행복이면 혼자서 몰입하고 회복하는 스타일을 설명하는 식으로 해석해야 한다.
- 장점, 주의점, 추천 행동을 함께 제시하는 리포트형 문장이 적합하다.


7. 앞으로의 큰 방향

현재는 출시 완료 후 운영 초입이다.
지금 당장 중요한 것은 기능 추가보다 사용자 반응을 모으는 것이다.

우선순위:
1. 앱 존재를 알리는 마케팅 시작
2. 초기 사용자 유입 만들기
3. 실제 사용 행동 데이터 확인
4. 어떤 기능이 쓰이고 안 쓰이는지 판단
5. 그 결과를 바탕으로 AI 기능을 붙일지 결정

마케팅 관점에서 볼 문장:
- 작은 행복을 기록하고, 다른 사람의 행복에 공감하며, 나의 행복 패턴을 분석하는 앱
- 일기보다 가볍고, SNS보다 조용한 행복 기록 앱
- 오늘 나를 웃게 한 순간을 모아두는 앱

초기 타깃 후보:
- 감정 기록이나 일기를 좋아하지만 긴 글은 부담스러운 사람
- 소확행, 루틴, 자기 돌봄 콘텐츠에 관심 있는 사람
- 무기력하거나 번아웃 상태에서 작은 회복 루틴을 찾고 싶은 사람
- 다른 사람의 소소한 행복을 보며 아이디어를 얻고 싶은 사람


8. AI 도입 전 확인할 것

AI를 바로 붙이기 전에 다음을 확인해야 한다.

- 사용자가 실제로 기록을 남기는가?
- 오늘의 행복을 쓰는가?
- 행복 리스트를 둘러보기만 하는가, 메모나 공감까지 하는가?
- 태그 선택이 귀찮게 느껴지지는 않는가?
- 분석 리포트가 사용자의 재방문 이유가 되는가?
- 공유 기능이 실제로 쓰이는가?
- 공감 기능이 즐겨찾기와 충분히 구분되는가?

AI는 사용 데이터가 충분히 쌓인 뒤 붙이는 것이 좋다.


9. AI 도입 예정 방향

AI 기능 후보:
- 기록과 메모 문장을 기반으로 감정과 맥락 분석
- 태그 자동 추천 / 자동 분류
- 나의 행복 성향 리포트 고도화
- 월간 / 주간 / 전체 분석 리포트
- 행복 목표 기능
- 사용자가 행복을 늘리기 위해 더 하면 좋은 행동과 줄이면 좋은 행동 제안
- 내가 자주 쓰는 단어, 자주 등장하는 상황, 감정 흐름 분석
- 추천 행복 개인화

행복 목표 기능 방향:
- 사용자가 "행복 목표"를 만든다.
- AI가 목표를 이루기 위해 어떤 행동을 늘리고 줄이면 좋을지 제안한다.
- 기존 기록, 메모, 태그, 공감 데이터를 참고한다.
- 이 기능은 출시 후 반응을 보고 나중에 구현한다.


10. 운영과 데이터 확인 방향

출시 후 봐야 할 지표:
- 설치 수
- 회원가입 수
- 첫 기록 작성률
- 오늘의 행복 작성률
- 행복 카드 클릭률
- 공감 클릭률
- 즐겨찾기 사용률
- 메모 작성률
- 분석 탭 진입률
- 2일차 / 7일차 재방문

Supabase에서 봐야 할 것:
- 계정 기반 데이터가 정상 저장되는지
- 게스트 데이터 잔여 흐름이 없는지
- 기록, 메모, 공감, 즐겨찾기, 내가 만든 행복 데이터가 정상 연결되는지
- 삭제 시 실제 데이터가 의도대로 사라지는지
- 알림 관련 데이터가 정상 동작하는지
- RLS 정책과 보안 설정에 문제가 없는지


11. 다른 AI가 작업할 때 주의할 점

사용자는 AI를 단순 코딩 도구가 아니라 함께 앱을 만드는 파트너로 본다.
따라서 단순히 요청만 수행하지 말고, 요청의 의도와 앱 방향에 맞는지 같이 판단해야 한다.

대답할 때 고려할 것:
1. 사용자의 말을 이해했는가?
2. 사용자의 말에 수정할 부분이 있는가?
3. 추가하거나 보완할 부분이 있는가?
4. 앞으로 어떻게 작업할지 계획이 있는가?
5. 전체적으로 어떤 의견을 갖고 있는가?

작업 규칙:
- 요청이 명확하지 않으면 짧게 확인 질문을 한다.
- 목적이나 방향이 애매하면 바로 구현하지 말고 목적을 묻는다.
- 사용자가 만든 변경분을 임의로 되돌리지 않는다.
- 비밀값, 토큰, 환경변수 값은 출력하지 않는다.
- Supabase 등 외부 서비스 작업에서는 민감정보를 노출하지 않고 상태만 확인한다.
- 커밋/푸시는 사용자가 요청했을 때 진행한다.
- AAB나 iOS 빌드 최신화가 필요한 작업인지 먼저 판단하고, 필요하면 사용자에게 알린다.


12. 현재 시점의 한 줄 요약

Happy Finder는 출시를 마친 작은 행복 기록/공감/분석 앱이며, 지금부터는 기능을 더 늘리기보다 마케팅으로 사용자 반응을 만들고, 실제 사용 데이터에 맞춰 AI 분석과 행복 목표 기능을 붙일지 판단해야 한다.
